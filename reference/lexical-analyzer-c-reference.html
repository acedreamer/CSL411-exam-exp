Lexical Analyzer in C Cheat Sheet

Token taxonomy, classification hierarchy, stream flush invariants, and examiner viva traps.

1. The 5 Token Categories Taxonomy

A lexical analyzer converts a continuous stream of characters into a sequence of discrete, categorized tokens:

Token Category Formal Definition & Pattern Example Lexemes Validation Invariant
Keyword Reserved words defined by the language grammar int, float, if, while, return Exact string match against predefined reserved keyword dictionary via is_keyword()
Operator Arithmetic, relational, logical, and assignment symbols +, -, *, /, =, ==, <, > Exact string match against operator symbol table via is_operator()
Special Symbol Punctuation, statement terminators, and block delimiters ;, ,, (, ), {, }, [, ] Match against delimiter character list via is_special()
Constant Unsigned integer or floating numeric literals ([0-9]+) 10, 42, 0, 365 Every character must strictly satisfy isdigit() via is_constant()
Identifier User-defined identifiers ([a-zA-Z_][a-zA-Z0-9_]*) a, b, sum, total_count Initial character must be letter or _; subsequent characters must be alphanumeric or _ via is_identifier()
Invalid Token Malformed characters or mixed illegal symbols 123abc, @#$ Fallback category when all five classification predicates return false

2. Classification Priority Hierarchy Table

Because the regular expression for identifiers ([a-zA-Z_][a-zA-Z0-9_]*) is a strict superset of all language keywords (e.g., int, return, if), classification order is critical. Testing identifiers before keywords causes catastrophic misclassification:

Priority Rank Classification Subroutine Condition Evaluated Why This Rank Is Enforced
Priority 1 is_keyword(buffer) Exact match in keyword dictionary Must intercept before Identifier check! Otherwise, keywords like int will be falsely claimed as variable names.
Priority 2 is_operator(buffer) Match in operator table (+, -, =, etc.) Direct categorization of packaged mathematical/relational operators.
Priority 3 is_special(buffer) Match in delimiter list (;, ,, (, ), etc.) Direct categorization of punctuation and structural delimiters.
Priority 4 is_constant(buffer) All characters satisfy isdigit() Separates pure numeric literals before identifier analysis begins.
Priority 5 is_identifier(buffer) Valid ANSI C identifier syntax rules Catches all remaining valid user-defined names having passed keyword filtering.
Fallback Else Branch Default catch-all Reports syntax errors / invalid tokens (e.g., digits followed by letters like 9xyz).

3. Character Stream Scanning & Buffer Flush Invariants

In standard C source code, whitespaces around operators are optional (e.g., a=b+10;). A naive scanner that splits only on whitespace will fail completely. The C scanner enforces three structural invariants:

  1. Whitespace Delimiter Invariant: When ch is space (' '), horizontal tab ('\t'), or newline ('\n'):
    • If idx > 0: null-terminate buffer[idx] = '\0', dispatch detect(buffer), and reset idx = 0.
    • If idx == 0: do nothing (skip multiple consecutive whitespaces).
  2. Self-Delimiting Operator / Symbol Flush Invariant: When ch is an operator or punctuation (+, -, *, /, =, ;, ,, etc.):
    • Step A (Preceding Flush): If idx > 0, null-terminate and flush the preceding lexeme (e.g., flushing "a" when seeing '='), then reset idx = 0.
    • Step B (Packaging): Package the current character into a temporary 2-byte null-terminated string temp[0] = ch, temp[1] = '\0', and dispatch detect(temp) immediately.
  3. End-of-File (EOF) Invariant: When fgetc() returns EOF, verify if (idx > 0). If true, null-terminate and dispatch detect(buffer) to ensure the trailing token without a trailing newline is never lost.

4. Minimal Reconstructible C Skeleton (< 45 Lines)

This compact, complete implementation fits entirely in active memory and can be reproduced on a blank sheet or exam terminal in under 3 minutes:

#include <stdio.h>
#include <string.h>
#include <ctype.h>
#include <stdbool.h>

char *kw[] = {"int","float","char","double","if","else","while","for","return","void"};
char *op[] = {"+","-","*","/","=","==","<",">","<=",">="};
char sp[] = ";,(){}[]";

bool is_kw(char *s) { for (int i=0; i<10; i++) if (!strcmp(s, kw[i])) return true; return false; }
bool is_op(char *s) { for (int i=0; i<10; i++) if (!strcmp(s, op[i])) return true; return false; }
bool is_num(char *s) { for (int i=0; s[i]; i++) if (!isdigit(s[i])) return false; return true; }
bool is_id(char *s) {
    if (!isalpha(s[0]) && s[0] != '_') return false;
    for (int i=1; s[i]; i++) if (!isalnum(s[i]) && s[i] != '_') return false;
    return true;
}

void detect(char *s) {
    if (!s[0]) return;
    if (is_kw(s)) printf("%-15s : Keyword\n", s);
    else if (is_op(s)) printf("%-15s : Operator\n", s);
    else if (strlen(s) == 1 && strchr(sp, s[0])) printf("%-15s : Special Symbol\n", s);
    else if (is_num(s)) printf("%-15s : Constant\n", s);
    else if (is_id(s)) printf("%-15s : Identifier\n", s);
    else printf("%-15s : Invalid Token\n", s);
}

int main() {
    FILE *fp = fopen("input.txt", "r");
    if (!fp) return printf("Error opening input.txt\n"), 1;
    char ch, buf[50]; int idx = 0;
    printf("%-15s   %s\n-----------------------------\n", "LEXEME", "TOKEN TYPE");
    while ((ch = fgetc(fp)) != EOF) {
        if (isspace(ch)) {
            if (idx > 0) { buf[idx] = '\0'; detect(buf); idx = 0; }
        } else if (strchr("+-*/=;,(){}[]<>", ch)) {
            if (idx > 0) { buf[idx] = '\0'; detect(buf); idx = 0; }
            char t[2] = {ch, '\0'}; detect(t);
        } else buf[idx++] = ch;
    }
    if (idx > 0) { buf[idx] = '\0'; detect(buf); }
    fclose(fp);
    return 0;
}

5. Examiner Viva Traps & Defense Points

Trap 1: What is the fundamental difference between a Lexeme, a Token, and a Pattern?
  • Pattern: The formal grammatical specification (usually expressed as a Regular Expression) describing what characters may constitute a given category. Example: [a-zA-Z_][a-zA-Z0-9_]* is the pattern for an identifier.
  • Lexeme: The concrete sequence of characters in the source code matching a pattern. Example: sum, total_count, 42, while.
  • Token: An abstract terminal category symbol returned by the lexical analyzer to the parser, optionally bundled with an attribute value. Example: <ID, &symbol_table_entry>, <KEYWORD, INT>, <NUM, 42>.
Trap 2: Why must is_keyword() be checked strictly BEFORE is_identifier()?

All C language keywords (like int, float, while, return) strictly adhere to the lexical pattern of identifiers: starting with an alphabet and followed by letters/digits. Therefore, the identifier regular expression is a proper superset containing all keywords. If identifier validation ran first, every single keyword would evaluate to true and be mistakenly reported as an Identifier!

Trap 3: How does this procedural C scanner compare to a LEX/Flex tool implementation?
  • Procedural C Scanner: Reads character-by-character and executes manual string comparison loops (strcmp, isdigit, isalpha) at token boundaries. Time complexity per lexeme scales with the number of keywords ($O(K \times L)$).
  • LEX/Flex Tool: Automatically translates regular expression patterns into a Deterministic Finite Automaton (DFA) state transition table using Thompson's construction and subset construction. State transitions occur in strictly $O(1)$ time per character, independent of how many keywords or patterns are declared.
Trap 4: How would you extend this program to handle single-line (//) and multi-line (/* ... */) comments?

When the scanner encounters a forward slash '/', it should peek at the next character using fgetc(fp):

  • If next is '/': discard characters in a while loop until '\n' or EOF is reached (single-line comment).
  • If next is '*': enter a loop discarding characters until encountering '*' immediately followed by '/' (multi-line comment).
  • If next is neither: push the character back onto the stream using ungetc(next, fp) and treat '/' as a standard arithmetic division operator.
Trap 5: How does the scanner handle multi-character relational operators like ==, <=, or !=?

In this basic implementation, single-character operators are emitted individually. To support multi-character operators, the scanner uses a lookahead: upon encountering '=', '<', '>', or '!', it reads the next character with fgetc(). If the next character is '=', it creates a 2-character string "==", "<=", ">=", or "!=" and calls detect(). If not, it uses ungetc() to push the second character back into the stream and emits the single operator.
