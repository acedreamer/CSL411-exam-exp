Shift-Reduce Parser Cheat Sheet

Grammar rules, dual-pointer stack mechanics, handle pruning table, and examiner viva traps.

1. Context-Free Grammar Rules

The parser operates on an arithmetic expression grammar consisting of four production rules:

Rule 1:  E → E + E     (Binary Addition)
Rule 2:  E → E * E     (Binary Multiplication)
Rule 3:  E → ( E )     (Parenthesized Expression)
Rule 4:  E → id        (Terminal Identifier)

Goal: Transform the terminal input stream into the start symbol E using bottom-up handle reduction.

2. Dual-Pointer Stack & Memory Layout

Variable Type Initial Value Operational Role
stack[50] char[] "" (empty) LIFO stack holding shifted terminals and reduced non-terminals.
input[50] char[] User input Terminal string buffer. Consumed tokens are overwritten with ' '.
k int 0 Stack top index pointer; represents current stack height / next push slot.
i int 0 Input stream scan index; advances left-to-right from 0 to len.
len int strlen(input) Total character length of the original input token string.

3. The check() Handle Identification Table

At every step, check() inspects the topmost elements of the stack. If a handle is discovered, it replaces the substring with 'E', adjusts k, null-terminates the stack string, and returns 1:

Rule Handle Pattern Stack Boundary Guard Reduction & Pointer Mechanics Return
E → id 'i', 'd' k >= 2 && stack[k-1]=='d' && stack[k-2]=='i' stack[k-2]='E'; stack[k-1]='\0'; k=k-1; 1
E → E+E 'E', '+', 'E' k >= 3 && stack[k-1]=='E' && stack[k-2]=='+' && stack[k-3]=='E' stack[k-3]='E'; stack[k-2]='\0'; k=k-2; 1
E → E*E 'E', '*', 'E' k >= 3 && stack[k-1]=='E' && stack[k-2]=='*' && stack[k-3]=='E' stack[k-3]='E'; stack[k-2]='\0'; k=k-2; 1
E → (E) '(', 'E', ')' k >= 3 && stack[k-1]==')' && stack[k-2]=='E' && stack[k-3]=='(' stack[k-3]='E'; stack[k-2]='\0'; k=k-2; 1
None No match Fallback No change to stack or pointer. 0

4. Minimal Reconstructible C Skeleton (< 45 Lines)

This compact, complete implementation fits entirely in active memory and can be reproduced on a blank sheet in under 3 minutes:

#include <stdio.h>
#include <string.h>

char in[50], st[50];
int k = 0, i = 0, len;

int check() {
    if (k >= 2 && st[k-1] == 'd' && st[k-2] == 'i') {
        st[k-2] = 'E'; st[k-1] = '\0'; k--;
        printf("%s\t\t%s\t\tREDUCE E->id\n", st, in); return 1;
    }
    if (k >= 3 && st[k-1] == 'E' && (st[k-2] == '+' || st[k-2] == '*') && st[k-3] == 'E') {
        char op = st[k-2]; st[k-3] = 'E'; st[k-2] = '\0'; k -= 2;
        printf("%s\t\t%s\t\tREDUCE E->E%cE\n", st, in, op); return 1;
    }
    if (k >= 3 && st[k-1] == ')' && st[k-2] == 'E' && st[k-3] == '(') {
        st[k-3] = 'E'; st[k-2] = '\0'; k -= 2;
        printf("%s\t\t%s\t\tREDUCE E->(E)\n", st, in); return 1;
    }
    return 0;
}

int main() {
    printf("Enter string (e.g., id+id*id): ");
    scanf("%s", in); len = strlen(in);
    printf("\nSTACK\t\tINPUT\t\tACTION\n-----\t\t-----\t\t------\n");
    while (i < len || !(st[0] == 'E' && st[1] == '\0')) {
        if (in[i] == 'i' && in[i+1] == 'd' && i + 1 < len) {
            st[k] = 'i'; st[k+1] = 'd'; st[k+2] = '\0';
            in[i] = in[i+1] = ' '; k += 2; i += 2;
            printf("%s\t\t%s\t\tSHIFT id\n", st, in);
            while (check());
        } else if (i < len) {
            st[k] = in[i]; char ch = in[i]; st[k+1] = '\0';
            in[i] = ' '; k++; i++;
            printf("%s\t\t%s\t\tSHIFT %c\n", st, in, ch);
            while (check());
        } else break;
    }
    if (st[0] == 'E' && st[1] == '\0') printf("\nACCEPT: Parsed successfully!\n");
    else printf("\nREJECT: Parsing terminated with error.\n");
    return 0;
}

5. Examiner Viva Traps & Defense Points

Trap 1: Shift-Reduce Conflict vs. Reduce-Reduce Conflict
  • Shift-Reduce Conflict: Occurs when the parser cannot decide whether to shift the next input symbol onto the stack or reduce the existing handle already on top of the stack. In the ambiguous grammar E → E + E | E * E, having E + E on the stack with * in the input creates a conflict: shifting * respects multiplication precedence, whereas reducing E + E enforces left-to-right evaluation. Defense: This C implementation resolves the conflict implicitly by greedily reducing any completed handle immediately before shifting.
  • Reduce-Reduce Conflict: Occurs when the topmost symbols on the stack simultaneously match the right-hand sides of two distinct production rules (e.g., A → id and B → id). The parser cannot determine which non-terminal to substitute.
Trap 2: Why must check() run in a while(check()); loop after each shift?

A single shift operation can trigger a chain of cascading reductions. For example, in id + id, shifting the second id reduces it to E. Now the stack contains E + E. If we used an if (check()), the function would exit after reducing id → E, leaving E + E unreduced and causing premature parser termination or rejection. The while (check()); ensures handle reduction repeats until the stack stabilizes.

Trap 3: What is the purpose of the k >= 2 and k >= 3 guards?

In C, negative array subscripting (e.g., stack[-1] when k = 1) accesses unallocated memory before the array boundary. Without boundary guards, checking stack[k-3] when only 1 symbol is on the stack causes undefined behavior, illegal memory dereferencing, or false handle matches with stack garbage.

Trap 4: Why do we write st[k-1] = '\0' or st[k-2] = '\0' during reduction?

C strings are terminated by the null byte. When replacing a 3-character handle (E+E) with a 1-character non-terminal (E), the stack length shrinks from k to k - 2. Setting stack[k-2] = '\0' guarantees that subsequent printf("%s", stack) calls will accurately print only the valid symbols on the stack without trailing orphaned characters.

Trap 5: What exact conditions define Acceptance?

Both conditions must hold simultaneously: (1) the input stream must be completely consumed (i >= len), and (2) the stack must contain solely the start symbol E (stack[0] == 'E' && stack[1] == '\0').
