FIRST Set of Grammar From Scratch

The telephone tree mental model, recursive base cases, set deduplication, and predictive parsing foundations.

Mission Alignment: Your objective is to write the complete C program for computing the FIRST set of any Context-Free Grammar (CFG) from memory on paper or a terminal. By the end of this lesson, you will master the two recursive base cases, the LHS=RHS array indexing contract, and the set deduplication invariant.

1. The Mental Model: The Telephone Tree Detective

To master the FIRST set algorithm without memorizing code, picture a detective interrogating symbols in a grammar with one single question:

"What is the very first terminal character you can say when you speak?"

  • Case A (The Terminal): If the detective asks a terminal like 'i', '+', or '(', it answers immediately: "I can only speak for myself! My first character is 'i'." No phone calls required. This is our base case.
  • Case B (The Non-Terminal): If the detective asks a non-terminal like E, it cannot speak directly. It checks its production rule E=TX and says: "I defer to my leading child T. Let me call T on the telephone and ask what it can say!"
  • The Chain: Detective calls T. T checks T=FY and calls F. F checks F=(E) and F=i. Aha! F begins with '(' and 'i', which are terminals. F tells T, and T tells E.
  • The Vanishing Act (Epsilon $): If a rule says X=$, the symbol says: "I can vanish into thin air!" It contributes '$' to the set so the parser knows this symbol is nullable.

2. The Data Contract: Fixed-Format Production Indexing

The program stores grammar rules as simple strings in a 2D character array char p[20][20]. Every rule is entered in rigid LHS=RHS format:

Index:   [0]     [1]     [2]     [3] ...
Rule:     E       =       T       X

Notice the fixed index invariant:

  • p[i][0] is always the Left-Hand Side (LHS) non-terminal symbol.
  • p[i][1] is always the separator character '='.
  • p[i][2] is always the all-important leading symbol of the Right-Hand Side (RHS).

To distinguish non-terminals from terminals, the program uses the standard C library function isupper() from <ctype.h>:

  • isupper(c) == true → Non-terminal (uppercase English letters 'A' through 'Z').
  • !isupper(c) == true → Terminal token (lowercase letters, operators like '+', '*', brackets '(', ')', and the epsilon marker '$').

3. Deconstructing first(char c): Two Essential Branches

The entire FIRST computation engine fits into 15 lines of clean C. It contains exactly two core branches:

void first(char c) {
    /* Case 1: Terminal base case (leaf node) */
    if (!isupper(c)) {
        add_to_result(c);
        return;
    }
    
    /* Case 2: Non-terminal recursive expansion */
    for (int i = 0; i < n; i++) {
        if (p[i][0] == c) {
            if (p[i][2] == '$') {
                add_to_result('$');          /* Sub-case 2a: Derives epsilon directly */
            } else if (!isupper(p[i][2])) {
                add_to_result(p[i][2]);      /* Sub-case 2b: RHS starts with terminal */
            } else {
                first(p[i][2]);              /* Sub-case 2c: RHS starts with non-terminal */
            }
        }
    }
}

Trace the elegance of this structure: if p[i][2] is a non-terminal, we recursively invoke first(p[i][2]). That recursive call will either hit a terminal base case (adding it to f) or chain further down until leaf terminals are reached.

4. Set Deduplication: add_to_result(char ch)

In set theory, duplicates are mathematically forbidden: $\{ i, (, i \}$ must be stored simply as $\{ i, ( \}$. To enforce this, results are never written directly to f[m++] without a uniqueness guard:

void add_to_result(char ch) {
    for (int i = 0; i < m; i++) {
        if (f[i] == ch) return; /* Symbol already present: drop duplicate */
    }
    f[m++] = ch;                /* New unique symbol: append and increment */
}
Exam Reminder: Before computing the FIRST set for a new non-terminal symbol in main(), you must reset the counter: m = 0;. Otherwise, results from earlier queries will contaminate the next set!

5. Complete Execution Trace: Standard KTU Grammar

Consider the classic expression grammar with left recursion eliminated:

1: E=TX     2: X=+TX    3: X=$
4: T=FY     5: Y=*FY    6: Y=$
7: F=(E)    8: F=i

Query: first('E')

  1. 'E' is uppercase → Scan productions for LHS 'E'. Rule 1 matches: E=TX.
  2. Leading RHS is p[0][2] = 'T' (uppercase) → Recursively call first('T').
  3. In first('T'): Rule 4 matches: T=FY. Leading RHS is 'F' → Recursively call first('F').
  4. In first('F'):
    • Rule 7 matches: F=(E). Leading RHS is '(' → !isupper('(') is true → Append '(' to set.
    • Rule 8 matches: F=i. Leading RHS is 'i' → !isupper('i') is true → Append 'i' to set.
  5. Calls unwind back to first('T') and then first('E').
  6. Result: FIRST(E) = { (, i }.
