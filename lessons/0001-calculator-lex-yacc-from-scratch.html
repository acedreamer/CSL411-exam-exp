Calculator Using LEX and YACC From Scratch

Deconstructing the contract between the Tokenizer and the Grammar Evaluator.

Mission Alignment: Your goal is to write both calc.l and calc.y from a completely blank screen without looking at notes. By the end of this 10-minute lesson, you will understand the three communication channels connecting LEX and YACC.

1. The Mental Model: The Translator & The Calculator

Most students fail to write LEX and YACC programs because they treat them as a single monolithic script. In reality, they are two distinct programs working in tandem:

  1. LEX is the Tokenizer (The Reader): Reads raw ASCII characters from the input stream, ignores spaces, converts sequences like "4", "5" into the integer 45, and hands tokens to YACC.
  2. YACC is the Grammar Evaluator (The Math Brain): Doesn't know or care about raw characters. It receives tokens like NUMBER, organizes them into an evaluation tree based on operator precedence, and executes arithmetic actions.

2. The Shared Pipeline: How the Files Connect

To compile the system, four files interact across a precise sequence:

Step 1: yacc -d calc.y       → Creates y.tab.c (grammar) and y.tab.h (tokens)
Step 2: lex calc.l           → Creates lex.yy.c (tokenizer)
Step 3: gcc lex.yy.c y.tab.c -w -o calc.out
Step 4: ./calc.out

The Golden Contract: Why do we run yacc -d first? Because calc.l needs to know what token ID NUMBER represents. YACC generates the header file y.tab.h, which calc.l includes.

3. File 1: calc.l (The Tokenizer)

LEX files have three sections separated by %%:

%{
#include <stdio.h>
#include "y.tab.h"    /* 1. Imports NUMBER token definition from YACC */
extern int yylval;    /* 2. Global mailbox to pass values to YACC */
%}

%%
[0-9]+      { yylval = atoi(yytext); return NUMBER; } /* Match digits */
[\n]        { return 0; }                             /* End of expression */
[ \t]       ;                                         /* Ignore whitespace */
.           { return yytext[0]; }                     /* Return literal operator */
%%

int yywrap() {
    return 1; /* Signals end of input stream */
}
The 3 rules you need to hold in your head:
  • Numbers: [0-9]+ → yylval = atoi(yytext); return NUMBER;
  • Newline: [\n] → return 0; (tells YACC parsing is finished)
  • Operators: . → return yytext[0]; (returns +, -, *, /, (, ) directly)

4. File 2: calc.y (The Evaluator)

YACC also has three sections, but here you define grammar rules and operator precedence.

A. Declarations & Precedence

%{
#include <stdio.h>
#include <stdlib.h>

int flag = 0;
int yylex();
void yyerror(const char *s);
%}

%token NUMBER
%left '+' '-'
%left '*' '/' '%'
%left '(' ')'

Precedence rule: Operators declared lower have higher precedence. Because * is written after +, YACC automatically evaluates multiplication before addition!

B. Grammar Productions & Semantic Actions

%%
Calculate : E {
    printf("The calculated value is: %d\n", $$);
} ;

E : E '+' E    { $$ = $1 + $3; }
  | E '-' E    { $$ = $1 - $3; }
  | E '*' E    { $$ = $1 * $3; }
  | E '/' E    { 
        if ($3 == 0) {
            printf("\nRuntime Error: Division by zero!\n");
            flag = 1;
            YYABORT;
        } else {
            $$ = $1 / $3;
        }
    }
  | E '%' E    { $$ = $1 % $3; }
  | '(' E ')'  { $$ = $2; }
  | NUMBER     { $$ = $1; }
  ;
%%

Deciphering the Dollar Signs:

  • $$ = The result of the left-hand side non-terminal (E).
  • $1 = The value of the first symbol on the right-hand side.
  • $2 = The operator symbol (e.g., '+').
  • $3 = The value of the third symbol on the right-hand side.

C. Driver & Error Routine

int main() {
    printf("Enter the arithmetic expression:\n");
    yyparse();
    if (flag == 0) {
        printf("Successful evaluation done.\n");
    }
    return 0;
}

void yyerror(const char *s) {
    flag = 1;
    printf("Invalid expression to calculate, unable to parse.\n");
}
