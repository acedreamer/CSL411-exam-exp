Intermediate Code Generator (TAC) From Scratch

Linearizing syntax trees into atomic three-address operations with operator precedence and relational jump cascades.

Mission Alignment: Your objective is to write the complete C program for Three-Address Code generation from memory on a blank sheet or IDE without looking at notes. By the end of this lesson, you will master the three modular generation recipes: assignment partitioning, precedence scanning, and the 4-slot relational jump template.

1. The Mental Model: The Assembly-Line Translator

Imagine a factory assembly line producing custom furniture. If an order arrives saying: "Build a varnished oak dining table with four tapered legs and brass caps," no single machine can fulfill this sentence in one step. The factory floor manager must decompose the instruction into elementary, two-input operations:

  1. t1 = cut_wood(oak, tabletop)
  2. t2 = carve_legs(oak, 4)
  3. t3 = attach(t1, t2)
  4. t4 = fit_caps(t3, brass)
  5. final_table = varnish(t4)

The Compiler's Dilemma: A CPU is just like that factory machine. A processor cannot execute a nested high-level expression like x = a + b * c - d in one stroke. It only knows how to load two registers, apply one arithmetic logic unit (ALU) operation, and store the result. Three-Address Code (TAC) is the linearized, intermediate language that bridges human syntax trees and physical machine registers.

2. What Makes Code "Three-Address"?

In standard Three-Address Code, every statement has at most one operator on the right-hand side and references at most three memory addresses (two sources and one destination):

x = y op z      /* General binary form: 3 addresses (x, y, z) */
x = op y        /* Unary form: 2 addresses (x, y)             */
x = y           /* Copy form: 2 addresses (x, y)              */
goto L          /* Unconditional jump: 1 address (target L)   */
if x relop y goto L  /* Conditional branch: 3 addresses (x, y, L) */

To evaluate complex statements, the compiler generates synthetic names called temporaries (temp, temp1, t1, etc.) to store intermediate sub-computations.

3. Deconstructing the Three Generation Recipes

In the KTU CSL411 lab implementation, the program handles three distinct categories of expressions via modular functions:

Recipe 1: Assignment Statements (assignment_tac)

Given an expression like a = b + c or a direct copy like a = b:

  1. Locate the Pivot: Scan the input string until encountering the '=' character. Everything to the left is the Left-Hand Side (lhs), and everything to the right is the Right-Hand Side (rhs).
  2. Operator Inspection: Traverse rhs to check for arithmetic operators (+, -, *, /).
  3. Emission Logic:
    • Compound RHS (e.g., b + c): Extract operand 1 (b), operator (+), and operand 2 (c). Emit: 
      temp = b + c
a = temp
    • Simple RHS (e.g., b): Emit: 
      temp = b
a = temp

Recipe 2: Arithmetic Expressions & Precedence (arithmetic_tac)

Consider the expression a + b * c versus a * b - c. A naive left-to-right evaluation would evaluate (a + b) first, violating mathematical precedence! To solve this without a full parsing tree, our generator uses a two-pass priority scan:

Pass 1 (High Precedence): Search for multiplication (*) or division (/).

  • If found at index op_idx, isolate the immediately adjacent characters: left operand exp[op_idx - 1] and right operand exp[op_idx + 1].
  • Emit the high-priority calculation: 
    temp = exp[op_idx - 1] exp[op_idx] exp[op_idx + 1]
  • Fold the remaining lower-precedence operation with temp:
    • If the remainder is to the right (e.g., a * b - c): emit temp1 = temp - c.
    • If the remainder is to the left (e.g., a + b * c): emit temp1 = a + temp.

Pass 2 (Low Precedence Fallback): If no * or / is present (e.g., a + b - c), evaluate strictly left-to-right:

temp = a + b
temp1 = temp - c

Recipe 3: Relational Expressions & The 4-Slot Jump Template (relational_tac)

Hardware ALUs do not directly produce boolean symbols like "true" or "false" from comparisons; they evaluate comparison conditions by testing zero flags and branching. The relational generator mirrors this through a classic four-quadruple boolean branching template:

Given the relational expression a <= b with starting address counter addr = 100:

100: if a <= b goto 103   /* Slot 1: If condition holds, jump straight to True */
101: T = 0                 /* Slot 2: Fall-through: condition failed, assign False */
102: goto 104              /* Slot 3: Unconditional jump to skip True assignment */
103: T = 1                 /* Slot 4: Target for True condition, assign True    */
(Next statement begins at 104)
Why increment addr += 4?
Notice that the template occupies exactly 4 address slots: addr, addr+1, addr+2, and addr+3. By incrementing addr by 4, the program ensures that subsequent instructions or future expressions start at addr+4, eliminating label collision!

4. Complete Reconstructible C Code

Study this minimal, clean implementation. Notice how the three functions cleanly isolate the generation logic:

#include <stdio.h>
#include <string.h>
#include <stdlib.h>

void assignment_tac(char exp[]);
void arithmetic_tac(char exp[]);
void relational_tac(char exp[]);

int addr = 100;

int main() {
    int ch;
    char exp[50];
    
    while (1) {
        printf("\n==========================================");
        printf("\n       THREE ADDRESS CODE GENERATOR       ");
        printf("\n==========================================");
        printf("\n1. Assignment Statement");
        printf("\n2. Arithmetic Expression");
        printf("\n3. Relational Expression");
        printf("\n4. Exit");
        printf("\nEnter choice (1-4): ");
        if (scanf("%d", &ch) != 1 || ch == 4) break;
        
        printf("Enter expression: ");
        scanf("%s", exp);
        
        switch (ch) {
            case 1: assignment_tac(exp); break;
            case 2: arithmetic_tac(exp); break;
            case 3: relational_tac(exp); break;
            default: printf("Invalid option!\n");
        }
    }
    return 0;
}

void assignment_tac(char exp[]) {
    int i = 0, l = strlen(exp);
    char lhs[10], rhs[20];
    
    while (exp[i] != '=' && i < l) {
        lhs[i] = exp[i];
        i++;
    }
    lhs[i] = '\0';
    
    if (i >= l) {
        printf("Syntax Error: Missing '=' operator.\n");
        return;
    }
    
    strcpy(rhs, &exp[i + 1]);
    
    int op_pos = -1;
    for (int j = 0; rhs[j] != '\0'; j++) {
        if (rhs[j] == '+' || rhs[j] == '-' || rhs[j] == '*' || rhs[j] == '/') {
            op_pos = j;
            break;
        }
    }
    
    printf("\nThree Address Code Generated:\n");
    if (op_pos != -1) {
        char op1[10], op2[10];
        strncpy(op1, rhs, op_pos);
        op1[op_pos] = '\0';
        strcpy(op2, &rhs[op_pos + 1]);
        printf("temp = %s %c %s\n", op1, rhs[op_pos], op2);
        printf("%s = temp\n", lhs);
    } else {
        printf("temp = %s\n", rhs);
        printf("%s = temp\n", lhs);
    }
}

void arithmetic_tac(char exp[]) {
    int l = strlen(exp);
    int op_idx = -1;
    
    for (int i = 0; i < l; i++) {
        if (exp[i] == '*' || exp[i] == '/') {
            op_idx = i;
            break;
        }
    }
    
    printf("\nThree Address Code Generated:\n");
    if (op_idx != -1) {
        /* High precedence operator found */
        printf("temp = %c %c %c\n", exp[op_idx - 1], exp[op_idx], exp[op_idx + 1]);
        if (op_idx + 2 < l) {
            printf("temp1 = temp %c %c\n", exp[op_idx + 2], exp[op_idx + 3]);
        } else if (op_idx - 2 >= 0) {
            printf("temp1 = %c %c temp\n", exp[op_idx - 3], exp[op_idx - 2]);
        }
    } else {
        /* Low precedence (+ and -) evaluated left-to-right */
        printf("temp = %c %c %c\n", exp[0], exp[1], exp[2]);
        if (l > 3) {
            printf("temp1 = temp %c %c\n", exp[3], exp[4]);
        }
    }
}

void relational_tac(char exp[]) {
    printf("\nThree Address Code Generated:\n");
    printf("%d: if %s goto %d\n", addr, exp, addr + 3);
    printf("%d: T = 0\n", addr + 1);
    printf("%d: goto %d\n", addr + 2, addr + 4);
    printf("%d: T = 1\n", addr + 3);
    addr += 4;
}
