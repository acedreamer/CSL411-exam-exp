Lexical Analyzer in C From Scratch

Stream scanning, buffer flush invariants, hierarchical classification, and keyword precedence.

Mission Alignment: Your objective is to design and write the complete C program for a Lexical Analyzer (Scanner) on a blank whiteboard or empty terminal without notes. By the end of this 12-minute lesson, you will master the two cooperating engines: the character stream scanner with delimiter flush guards and the 5-tier hierarchical token classifier.

1. The Mental Model: The Automated Mail Sorting Conveyor

Before a compiler can check grammar or generate code, it must transform raw text into meaningful semantic units. Source code enters as an unstructured stream of characters: 'i', 'n', 't', ' ', 'a', '=', '1', '0', ';'.

Think of the lexical analyzer as an Automated Mail Sorting Conveyor Belt:

  1. The Stream Feeder (fgetc): Characters arrive one-by-one on a moving conveyor belt from the input file.
  2. The Postal Bag (buffer[50]): When alphanumeric letters and digits appear, they drop into a collection bag. Each new character appends to the bag (buffer[idx++] = ch).
  3. Whitespace Gaps (Spaces, Tabs, Newlines): A whitespace signifies empty belt space. When a gap appears, if the bag contains mail (idx > 0), we seal it with a null terminator ('\0'), slide it to the inspection counter (detect(buffer)), and reset the bag pointer (idx = 0).
  4. Mechanical Lane Dividers (Operators & Punctuation): Symbols like =, +, or ; act as physical metal dividers on the conveyor belt. When an envelope hits a divider, two events fire in instant succession:
    • Step A: The preceding package in the bag is immediately sealed and classified (e.g., flushing "a" when hitting '=').
    • Step B: The divider itself is packaged into a mini-envelope (temp[0]=ch, temp[1]='\0') and classified immediately as an Operator or Special Symbol.
  5. The Final Sweep (EOF Guard): When the conveyor stops at End-Of-File, any remaining letters in the bag are sealed and processed so nothing gets left behind.

2. Why Naive Tokenizers (like strtok) Fail

Beginners often ask: "Why can't we just read the file line-by-line with fgets() and split strings using strtok(line, " ")?"

Consider this standard, syntactically valid C statement:

a=b+10;

Because there is not a single whitespace in that line, strtok(line, " ") returns the entire string "a=b+10;" as one gigantic token! The parser has no way to decipher where the variable ends and the assignment operator begins. A true compiler scanner must inspect characters at the stream level and treat punctuation symbols as self-delimiting token boundaries.

3. Component 1: The Character Stream Scanner Engine

The scanner loop consumes characters directly from the file pointer using fgetc(). It maintains a 50-byte accumulator buffer and an integer write index idx:

FILE *ptr = fopen("input.txt", "r");
char ch;
char buffer[50];
int idx = 0;

while ((ch = fgetc(ptr)) != EOF) {
    /* Case 1: Whitespace Delimiters */
    if (ch == ' ' || ch == '\t' || ch == '\n') {
        if (idx > 0) {
            buffer[idx] = '\0';  /* Seal string */
            detect(buffer);      /* Classify lexeme */
            idx = 0;             /* Reset bag */
        }
    }
    /* Case 2: Self-Delimiting Operators & Special Symbols */
    else if (ch == '+' || ch == '-' || ch == '*' || ch == '/' || ch == '=' ||
             ch == ';' || ch == ',' || ch == '(' || ch == ')' || 
             ch == '{' || ch == '}' || ch == '[' || ch == ']') {
        
        /* Flush preceding token if packed without spaces (e.g., "a=") */
        if (idx > 0) {
            buffer[idx] = '\0';
            detect(buffer);
            idx = 0;
        }
        /* Package single punctuation character into string */
        char temp[2] = {ch, '\0'};
        detect(temp);
    }
    /* Case 3: Alphanumerics & Numeric Digits */
    else {
        buffer[idx++] = ch;
    }
}

/* Guard: Flush any trailing token before EOF */
if (idx > 0) {
    buffer[idx] = '\0';
    detect(buffer);
}
fclose(ptr);
The Self-Delimiting Flush Invariant: Look closely at Case 2. If the scanner reads a=b, the buffer holds "a" when ch becomes '='. The guard if (idx > 0) detects this uncommitted token, flushes "a" to detect(), resets idx = 0, and only then emits '=' via temp. This guarantees zero lost tokens regardless of whitespace styling!

4. Component 2: The Hierarchical Classifier detect()

Once a candidate lexeme is isolated, it is passed to detect(char buffer[]). The classifier executes five validation subroutines in a strict priority waterfall:

Priority Subroutine Matching Logic Emitted Category
1 is_keyword(buffer) Compares against reserved array: int, float, if, while, etc. Keyword
2 is_operator(buffer) Compares against operator array: +, -, *, /, =, etc. Operator
3 is_special(buffer) Compares against delimiter array: ;, ,, (, ), {, }, etc. Special Symbol
4 is_constant(buffer) Iterates through characters: all must satisfy isdigit(c) Constant
5 is_identifier(buffer) Checks first char (letter/_), then remaining chars (alnum/_) Identifier
Fallback Default Else Lexeme matches none of the 5 valid grammar categories Invalid Token
The "Keyword Before Identifier" Precedence Trap:

Why is Priority 1 mandatory? In ANSI C, an identifier is defined by the regular expression [a-zA-Z_][a-zA-Z0-9_]*.

Now look at the keyword int. Does it start with a letter? Yes ('i'). Are the remaining characters letters or digits? Yes ('n', 't').

Therefore, every single keyword in the C language is structurally a valid identifier! If you place is_identifier() above is_keyword() in your if-else chain, every keyword will be captured as a variable name, and zero keywords will ever be reported. Checking keywords first intercepts and reserves them.
