Shift-Reduce Parser From Scratch

Bottom-up handle pruning, dual-pointer stack mechanics, and cascading reduction loops.

Mission Alignment: Your objective is to write the complete C program for a Shift-Reduce Parser on a blank sheet or empty terminal without notes. By the end of this 10-minute lesson, you will master the two cooperating engines: the check() handle pruner and the main() shift-loop driver.

1. The Mental Model: The Tetris Conveyor Belt

Top-down parsers (like Recursive Descent or LL(1)) try to predict the parse tree from the root down to the leaves. Bottom-up parsers do the exact opposite: they begin at the leaves (the raw input tokens) and assemble them upward until only the root symbol E remains.

Think of bottom-up parsing like a game of Tetris with Russian nesting dolls:

  1. SHIFT (Feed a block): You slide blocks from the input stream onto a LIFO conveyor belt (the stack). As long as the blocks on top don't form a recognizable shape, you keep shifting new tokens in.
  2. REDUCE (Snap and collapse): The instant the top blocks form a recognized grammar pattern (a handle, such as id, E + E, E * E, or (E)), BAM! The entire sequence snaps together and collapses into a single golden block: E.
  3. CASCADE (Chain reaction): That newly collapsed E might now complete another combination with older blocks sitting underneath it! The parser immediately collapses that combo too, looping until no further reduction is possible.
  4. ACCEPT (Victory): When all input blocks have been shifted, the input stream is empty, and exactly one golden E sits on the stack, the parse is complete and accepted.

2. The Data Architecture: Two Pointers on Arrays

Unlike complex parser generators that require multi-state transition tables, a handwritten shift-reduce parser in C relies on two simple character arrays and two integer pointers:

char input[50];  /* The input token buffer (e.g. "id+id*id") */
char stack[50];  /* The LIFO parsing stack */
int k = 0;       /* Stack top pointer (current stack length / next push index) */
int i = 0;       /* Input read pointer (scans tokens left to right) */
int len;         /* Total length of the input string */
The In-Place Blanking Trick: When the parser shifts a character from input[i] to stack[k], it replaces input[i] = ' '. Why? When printf("%s", input) is executed at each step, the terminal displays only the remaining unread tokens, creating a beautiful scrolling animation in the tabular output!

3. Engine 1: check() — The Handle Pruner

In compiler theory, a handle is a substring on the stack that matches the right-hand side of a production rule whose reduction represents one step along the reverse of a rightmost derivation.

The check() subroutine inspects the topmost symbols of stack using a lookback window. If a handle is discovered, it executes three atomic steps:

  1. Replaces the leftmost character of the handle with 'E'.
  2. Null-terminates the string immediately after 'E'.
  3. Adjusts stack pointer k backward and returns 1 (signaling a reduction occurred).
int check() {
    /* 1. Handle: E -> id (Length 2) */
    if (k >= 2 && stack[k - 1] == 'd' && stack[k - 2] == 'i') {
        stack[k - 2] = 'E';      /* Replace 'i' with 'E' */
        stack[k - 1] = '\0';     /* Terminate string */
        k = k - 1;               /* Stack shrinks by 1 (2 chars become 1) */
        printf("%s\t\t%s\t\tREDUCE E->id\n", stack, input);
        return 1;
    }
    /* 2. Handle: E -> E + E (Length 3) */
    else if (k >= 3 && stack[k - 1] == 'E' && stack[k - 2] == '+' && stack[k - 3] == 'E') {
        stack[k - 3] = 'E';      /* Replace first 'E' with 'E' */
        stack[k - 2] = '\0';     /* Terminate string */
        k = k - 2;               /* Stack shrinks by 2 (3 chars become 1) */
        printf("%s\t\t%s\t\tREDUCE E->E+E\n", stack, input);
        return 1;
    }
    /* 3. Handle: E -> E * E (Length 3) */
    else if (k >= 3 && stack[k - 1] == 'E' && stack[k - 2] == '*' && stack[k - 3] == 'E') {
        stack[k - 3] = 'E';
        stack[k - 2] = '\0';
        k = k - 2;
        printf("%s\t\t%s\t\tREDUCE E->E*E\n", stack, input);
        return 1;
    }
    /* 4. Handle: E -> (E) (Length 3) */
    else if (k >= 3 && stack[k - 1] == ')' && stack[k - 2] == 'E' && stack[k - 3] == '(') {
        stack[k - 3] = 'E';
        stack[k - 2] = '\0';
        k = k - 2;
        printf("%s\t\t%s\t\tREDUCE E->(E)\n", stack, input);
        return 1;
    }
    return 0; /* No handle found on top of stack */
}
Crucial Safety Invariant: Notice the boundary checks k >= 2 and k >= 3. If the stack only contains one character (k == 1) and you check stack[k - 3], C accesses stack[-2]! This causes undefined behavior, illegal memory dereferencing, or false matches with garbage memory.

4. Engine 2: The Main Parsing Loop & Cascades

The parser operates in a while loop as long as unconsumed input exists OR the stack has not yet reduced cleanly to "E":

while (i < len || !(stack[0] == 'E' && stack[1] == '\0')) {
    /* Case A: Terminal is the two-character identifier "id" */
    if (input[i] == 'i' && input[i + 1] == 'd' && (i + 1) < len) {
        stack[k] = input[i];
        stack[k + 1] = input[i + 1];
        stack[k + 2] = '\0';
        input[i] = ' ';
        input[i + 1] = ' ';
        k += 2;
        i += 2;
        printf("%s\t\t%s\t\tSHIFT id\n", stack, input);
        while (check()); /* Cascading reduction loop! */
    }
    /* Case B: Single-character terminal (+, *, (, )) */
    else if (i < len) {
        stack[k] = input[i];
        char temp = input[i];
        stack[k + 1] = '\0';
        input[i] = ' ';
        k++;
        i++;
        printf("%s\t\t%s\t\tSHIFT %c\n", stack, input, temp);
        while (check()); /* Cascading reduction loop! */
    } 
    else {
        printf("\nREJECT: String cannot be parsed.\n");
        return 0;
    }
}
The Magic of while (check());: Why a while loop instead of an if? Consider shifting the second id in id + id. The stack becomes E + id.
  • First pass of check(): Identifies handle id → reduces to E. Stack is now E + E. check() returns 1.
  • Second pass of check(): The loop runs again! It finds handle E + E → reduces to E. check() returns 1.
  • Third pass of check(): No handle matches E. check() returns 0, breaking the loop.
A single if would have left E + E stuck on the stack!

5. Complete Execution Trace: id+id*id

Here is the exact step-by-step trace generated by the parser for the input expression id+id*id:

Step Stack Input Buffer Action Executed
1 id +id*id SHIFT id
2 E +id*id REDUCE E → id
3 E+ id*id SHIFT +
4 E+id *id SHIFT id
5 E+E *id REDUCE E → id
6 E *id REDUCE E → E+E (Greedy Reduction)
7 E* id SHIFT *
8 E*id SHIFT id
9 E*E REDUCE E → id
10 E REDUCE E → E*E
11 E ACCEPT String parsed successfully!
