Constant Propagation & Folding From Scratch

The quadruple data model, the evaluation guard, and the forward substitution domino effect.

Mission Alignment: Your objective is to write the complete C program for constant propagation on paper or terminal without referencing external material. By the end of this lesson, you will master the 4 invariant logical steps that govern the optimization.

1. The Mental Model: The Spreadsheet Conveyor Belt

Rather than thinking of this program as complex compiler theory, picture a four-column spreadsheet where each row is an instruction:

[ op ]   [ op1 ]   [ op2 ]   [ res ]   [ flag ]

Two distinct optimizations occur in one pass:

  • Constant Folding: If both inputs on a row are already numbers (e.g., 3 + 5), we compute 8 immediately at compile-time and mark the row as eliminated (flag = 1).
  • Constant Propagation: We take that result (8) and walk forward to all future rows, replacing any mention of the target variable with "8".

2. The Data Structure: Why Strings?

The core data model is a simple structure array:

struct expression {
    char op[2];   /* Operator string: "+", "-", "*", "/", "=" */
    char op1[5];  /* First operand: can be variable "a" or number "3" */
    char op2[5];  /* Second operand: variable "b", number "5", or dummy "?" */
    char res[5];  /* Result identifier: "c" */
    int flag;     /* 0 = Active (to print), 1 = Dead / Folded (suppress) */
} arr[10];
Key Architectural Detail: Why are op1 and op2 strings instead of integers? Because when the program starts, they might hold variable names like "a". Once optimized, they get replaced with string digits like "3". Character arrays hold both seamlessly.

3. The Evaluation Guard: When Can We Fold?

Inside constant(), the program scans each row i from 0 to n - 1. A row is eligible for evaluation if and only if one of two conditions holds:

if ((isdigit(arr[i].op1[0]) && isdigit(arr[i].op2[0])) ||
    (strcmp(arr[i].op, "=") == 0 && isdigit(arr[i].op1[0]))) {
    /* Safe to calculate! */
}
  1. Binary Arithmetic: Both operands begin with a digit character (e.g., + 3 5 b).
  2. Direct Assignment: The operator is "=" and the first operand is a digit (e.g., = 3 ? a).

4. The Forward Domino Effect: change()

Once a row is calculated, two things happen:

  1. We set arr[i].flag = 1. This marks the assignment as dead code so output() skips it.
  2. We call change(i, ans) to propagate the value downstream:
void change(int i, int res) {
    char buf[5];
    sprintf(buf, "%d", res); /* Convert integer result back to string */

    /* Notice: Loop strictly starts at i + 1! */
    for (int j = i + 1; j < n; j++) {
        if (strcmp(arr[i].res, arr[j].op1) == 0) strcpy(arr[j].op1, buf);
        if (strcmp(arr[i].res, arr[j].op2) == 0) strcpy(arr[j].op2, buf);
    }
}

Why j = i + 1? In straight-line code, instructions only affect statements placed after them, never before.
